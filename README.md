# GlowSignal

نظام تحليلي لبراندات التجميل والعناية بالشعر، يربط الإنفاق الإعلاني بجودة العملاء والطلبات المُسلّمة.

## الحالة الحالية: Cloud MVP 0.3
- مساحة عمل لتحليل ملفي CSV: الحملات، والعملاء والطلبات.
- حساب الإنفاق، العملاء الفريدين، التأهيل، الطلبات المُسلّمة، الإيراد، التكاليف المسجلة، ومساهمة تقديرية بعد الإعلان.
- مقارنة الحملات، تحليل الاعتراضات، ومؤشرات فريق المبيعات.
- تسجيل حساب بالبريد الإلكتروني وكلمة المرور عبر Supabase Auth.
- إنشاء مساحة عمل مستقلة لكل حساب وحفظ البيانات في Supabase Postgres مع Row Level Security.
- حفظ محلي احتياطي في المتصفح.
- لا توجد بعد اشتراكات أو تحصيل مدفوعات أو تكامل مباشر مع Meta / WhatsApp / TikTok.

## إعداد Supabase
1. افتح مشروع Supabase ثم SQL Editor.
2. افتح ملف `supabase/schema.sql` في هذا المستودع، وانسخ محتواه كاملًا إلى SQL Editor ثم اضغط Run. الملف قابل لإعادة التشغيل.
3. من Authentication → URL Configuration:
   - Site URL: `https://mabdelstar466-dotcom.github.io/profitos-egypt/`
   - أضف إلى Redirect URLs: `https://mabdelstar466-dotcom.github.io/profitos-egypt/**`
4. افتح مساحة العمل، وأنشئ حسابًا ببريدك وكلمة مرور لا تقل عن 8 أحرف. إذا طُلب تأكيد البريد، افتح رسالة التأكيد ثم ارجع وسجّل الدخول.
5. ارفع ملفات CSV. سيُحفظ كل استيراد داخل مساحة العمل السحابية.

## CSV imports
### Campaign file
Required: `campaign_name`, `spend`
Optional: `date`, `impressions`, `clicks`, `messages`

### Leads and orders file
Required: `lead_id`, `campaign_name`
Optional: `created_at`, `lead_status`, `objection`, `agent`, `first_response_minutes`, `order_id`, `order_status`, `order_value`, `product_cost`, `shipping_cost`, `return_cost`, `payment_fees`

استخدم معرّفات داخلية مجهولة. لا ترفع أسماء العملاء أو أرقام هواتفهم أو عناوينهم أو نصوص محادثاتهم.

## تعريف المؤشرات
المساهمة التقديرية = إيراد الطلبات المُسلّمة - تكلفة منتجاتها - الشحن المسجل - تكاليف المرتجعات - رسوم الدفع - الإنفاق الإعلاني.
هذا ليس صافي ربح محاسبيًا؛ لا يشمل المصاريف العامة والرواتب والضرائب والخصومات وأي تكلفة غير مسجلة.

إسناد الحملة مطابقة بسيطة لاسم الحملة، وليس إسنادًا متعدد اللمسات. إذا اختلفت أسماء الحملات بين الملفات فلن تتطابق تلقائيًا.

## الخصوصية والأمان
- مفتاح Supabase المستخدم في الواجهة هو Publishable Key فقط؛ لا تضع Service Role Key أو أي سر في ملفات الموقع.
- عزل مساحات العمل يتم عبر سياسات Row Level Security في قاعدة البيانات.
- الملفات المرفوعة تُرسل إلى قاعدة بيانات مساحة العمل بعد تسجيل الدخول؛ لذلك استخدم بيانات تشغيلية مجهولة الهوية فقط.
- الحفظ المحلي ليس بديلًا عن النسخ الاحتياطي.

## خارطة الطريق قبل البيع التجاري
1. اختبار الاستخدام مع 3–5 براندات تجميل وعناية شعر.
2. إضافة أدوار فريق ودعوات أعضاء ومراجعة الأمان.
3. إضافة ربط Meta الرسمي بعد إنشاء تطبيق مطور واستكمال الصلاحيات والمراجعات المطلوبة.
4. دراسة تكامل WhatsApp Business Platform وTikTok بعد الموافقات المطلوبة.
5. اختيار مزود دفع مناسب للسوق المستهدف وتفعيل الاشتراكات بعد التحقق من المتطلبات القانونية والتجارية.
6. اختبار تحميل البيانات، استعادة النسخ الاحتياطية، ومراقبة الأخطاء قبل استقبال عملاء يدفعون.
